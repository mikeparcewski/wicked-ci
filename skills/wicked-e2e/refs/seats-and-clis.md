# seats-and-clis: the agent CLIs crew runs as workers

## Setup quirks

- **Sign-in prerequisites per CLI.** A real sign-in is a provider login, so every
  `seats.signin.*` capability except agy is a `manual` (`human-gui`) oracle: never a pass. What each needs:
  - claude: the claude CLI on the host floor, or `claude setup-token` for the container floor,
    and a provider subscription.
  - codex: the codex CLI; the container floor needs a browser on the host for the ChatGPT login.
  - copilot: the copilot CLI and a GitHub Copilot entitlement (device code on the container floor).
  - opencode: the opencode CLI; a provider is optional (the free tier reads "no sign-in needed").
  - pi: the pi CLI and a supported provider account.
  - agy (Antigravity): off by default; it needs the agy CLI and a `clis.toml` overlay.
- **Credentials are never read.** A dep that names a provider account, an API key or the OS
  keychain is never met by the runner, so its capability reports `skipped` with that dep.
- **Shimmed seats are not sign-ins.** On the fixture target the smoke harness provides shimmed
  seats. They prove the wire and the roster, not that a real CLI is signed in.
- **Live.** On `--target live` the runner reads the daemon's `/roster` to see which seats are
  signed in (read-only). A capability that needs a signed-in seat the roster does not show is
  skipped.
- **Floors.** Container-floor capabilities need a container runtime whose `info` answers; host-floor
  ones need the CLI on the daemon host's PATH.
- **Councils.** `L` items convene councils (several seat CLIs at once). Run them one at a time.
