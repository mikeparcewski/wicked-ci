# plugins-and-installs: installers, the garden plugin per host, editor packs, MCP servers

## Setup quirks

- **Editor packs install through crew's consent gate.** An editor pack install runs crew's
  conformance check first, then parks at a consent gate the operator approves. A capability on
  that path drives a real install on its daemon, so it runs only against a proof daemon
  (`proof crew daemon`), never the operator's :7701.
- **Sandboxed homes.** Installer capabilities need a sandboxed HOME, config dir or Claude dir
  (`sandboxed HOME`, `sandboxed Claude dir`). The scenario sets it up. Never point an installer
  scenario at a real CLI config directory.
- **Stubs.** Many installer deps read "claude CLI or stub" / "codex or stub". The test's stub
  satisfies them, so no real CLI is needed.
- **Network.** Installs from npm or the marketplace need the network (`network` deps, probed by a
  DNS lookup of the npm registry).
- **Cost.** Most items here are `S` or `M`. An `L` item is an install that goes through a governed
  editor-plugin workflow.
