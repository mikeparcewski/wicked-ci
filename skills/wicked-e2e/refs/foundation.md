# foundation: wicked-bus, wicked-vault, wicked-ledger and the shared wicked-ci tooling

## Setup quirks

- **Bus.** Bus capabilities run against a temp bus root (`temp WICKED_BUS_DATA_DIR`), and most
  depend on `foundation.bus.init`, which their scenario's setup performs. Never point them at a
  shared bus.
- **Vault.** Vault capabilities need the `wicked-vault` CLI. The e2e runner itself seals every run
  in the run directory's own vault (`<run-dir>/.wicked-vault`), never an ancestor's.
- **Ledger.** wicked-ledger is a library with no CLI; its capabilities are proven by tests that
  import it.
- **CI tooling.** The wicked-ci reusable-workflow capabilities read GitHub (`GitHub`, `gh-auth`
  deps); the runner's gh reads are read-only.
- **Node.** Some foundation capabilities need `node>=22`, others `node>=20`; both are probed on PATH.
- **No adapter yet** for the bus, vault and installer suites: those capabilities report
  `skipped: adapter:none` until one exists.
