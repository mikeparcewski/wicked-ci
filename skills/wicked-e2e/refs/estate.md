# estate: the code graph, memory and knowledge store

## Setup quirks

- **Binaries on PATH.** Estate capabilities name `wicked-estate` and `wicked-estate-mcp`. The
  runner only checks that they are on PATH. It never starts them, and it never touches an
  operator's estate store.
- **Most estate scenarios have no adapter yet.** Estate's own suites (Rust tests in the estate
  repo) are not run by any adapter, so most estate capabilities report `skipped: adapter:none`.
  The plan says how many before anything runs.
- **Indexed graph.** Many capabilities need an indexed graph (`indexed graph`,
  `indexed fixture graph`). That is scenario setup, recorded as `unchecked`, not probed.
- **Write mode.** Capabilities that need `wicked-estate-mcp (write mode)` write to a store. Only
  run them against a throwaway store, never the operator's.
- **Consumers.** Garden and crew consumers of estate (the `mem`/`search` skill domains, crew's
  grounding) need the garden plugin too; see `refs/garden.md`.
