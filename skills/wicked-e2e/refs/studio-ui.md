# studio-ui: the studio pages, controls and run panels

## Setup quirks

- **Two targets, two meanings.** `--target fixture` drives the studio's fixture journeys
  (`wicked-studio:e2e/*_test.py` through `e2e/run_journeys.py`) against the in-process uxfix stub
  API. That fidelity is `e2e-fixture`: evidence, never a pass. Only `--target live --studio URL
  --live-journeys` runs the `e2e-live` journeys against a real crew daemon that serves its bundled
  studio, and those journeys drive that daemon for real (some launch governed runs). Ask first.
- **Checkout and build.** It needs a `wicked-studio` checkout under `--src DIR` (or
  `--checkout wicked-studio=PATH`). The journeys use the built studio; `--studio-rebuild` rebuilds
  `dist-sameorigin` first and adds build time.
- **Browser.** `--python` must name a Python that has Playwright, and `--playwright-browsers` the
  browser cache it installed. Without a launchable Chromium every journey is skipped.
- **Evidence.** Every UI capability requires `video` (`.webm`), `screenshot` (`.png`) and `trace`
  (`.zip`). A scenario that cannot record a browser (a smoke step, a unit test) leaves the
  capability `skipped: evidence:video,screenshot,trace` or `error`, never a verdict.
- **Unit tests are not journeys.** Many studio capabilities cite only studio unit tests. No adapter
  runs those yet, so they report `skipped: adapter:none`.
- **Never the operator's daemon.** A live studio URL on port 7701 or 7721 is refused. Start a
  throwaway `wicked-crew serve --port <free>` with its own state home and certify that.
