# interactive-and-docs: the document engine, its crew/studio seams, the product sites

## Setup quirks

- **The bridge is crew's.** wicked-interactive has no standalone UI. Crew spawns it as a local
  bridge and proxies it (`/d/:doc` routes), so most document capabilities need a crew daemon and
  the bridge (`interactive bridge`, `interactive.cli.serve-daemon`).
- **Documents first.** Many capabilities depend on a created document
  (`interactive.doc.create-html`). That is a prerequisite their scenario's setup performs.
- **Rendering and demos.** HTML/PDF rendering and demo recording need Playwright Chromium, and
  demo video needs `ffmpeg` on PATH.
- **Sites.** The product-site capabilities read public URLs and need the network.
- **No adapter yet.** Interactive's own test suites are not run by an adapter, so capabilities
  proven only there report `skipped: adapter:none`.
