# core-engine: wicked-core, the engine behind crew

## Setup quirks

- **Cargo tests.** Core scenarios run as `cargo test` in a `wicked-core` checkout (`--src DIR`).
  Pass `--build-slot "<prefix> --"` so heavy builds are serialised, and `--cargo-target-dir` to
  reuse a warm target dir. A cold build of the engine takes many minutes and dominates the plan's
  estimate.
- **Cargo is integration fidelity.** A cargo test yields a test report only (the engine's durable
  event logs stay in the test's temp dir), so a core capability proven by cargo is at most
  `partial`. Event checks on CoreEvents need a run-scoped event log, which only a smoke or live
  scenario records.
- **Container runtime.** Container-floor capabilities need `docker`, `podman` or `nerdctl` whose
  `info` answers. Without one they report `skipped` naming the container dep.
- **Studio-driven engine capabilities.** Several engine capabilities start from the studio
  (`studio:bundled-dist`, `crew:daemon-hermetic`, `playwright-chromium`): they need the studio
  setup of `refs/studio-ui.md` as well.
- **Governed runs.** `L` items launch governed runs whose councils spawn several seat CLIs at
  once. Never run two at the same time.
