# crew-api: the crew daemon wire, CLI and MCP server

## Setup quirks

- **Fixture = the smoke harness and crew's own tests.** On `--target fixture` the wicked-ci smoke
  steps (`smoke/lib/steps/Sxx-*.mjs`) boot published artifacts with shimmed seats in a temp root
  (`e2e-hermetic`, which can certify), and crew's vitest files run in-process (`integration`,
  which cannot). The smoke harness needs node >= 22 and the npm registry (it installs the
  published packages).
- **Checkout for vitest.** Crew's vitest scenarios need a `wicked-crew` checkout with its
  `node_modules` installed (`--src DIR`). Without it they report `skipped: checkout:wicked-crew`.
- **Live = read-only.** On `--target live` the runner itself sends only GETs under `/api/v1/` to
  `--studio URL`. A capability whose path is a POST is proven only by a scenario that drove it,
  never by the runner repeating the request.
- **Cost L = a governed run.** An `L` capability's path is a governed run with councils. On a real
  daemon that convenes a council of real seats per phase. Run L items one at a time.
- **Deps.** `daemon`, `real-engine`, `signed-in-seats` and `registered-repo` are provided by the
  smoke harness on the fixture target (shimmed seats prove the wire, not a real sign-in). On the
  live target they are probed read-only (`/health`, `/diagnostics`, `/roster`, `/repos`).
- `gh-auth` deps are probed with `gh auth status`; the runner never reads a token.
